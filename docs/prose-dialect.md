# 散文ブロックの Markdown 方言(PYN)

## <a id="prose-dialect"></a>散文ブロックの Markdown 方言

<sub>`spec` `prose-dialect`</sub>

- `applies_to`: `"canonical JSON の prose[]"`
- `decided_by`: `q-03`
- `generated_doc`: `docs/prose-dialect.md`
- `implemented_in`: `pyn/model.py`, `pyn/refs.py`, `pyn/render_html.py`, `pyn/render_md.py`
- `status`: `normative`

PYN の散文ブロック(投影A/投影B では三連引用符で囲む部分、正準形では `prose[]`)に
何を書いてよいかを定める。q-03 の決定は実装済みだったが明文化されていなかった
(t-12)。

この文書自身が `.pyn` で書かれており、`docs/prose-dialect.md` はその Markdown 射影
である。仕様が実物で例示されている状態を保つため、`.md` を手で編集しないこと。

### <a id="pd-principle"></a>原則: 検証できる意味だけを構造に置く

<sub>`section` `pd-principle`</sub>

方言を切る基準はひとつだけ。**その記法が文書のデータモデルに参加するかどうか**。

- 参加する(=検証・解決の対象になる)ものは、構造か参照として扱う
- 参加しないもの(太字・斜体など純粋な装飾)は Markdown に素通しする

この線引きが [禁止する記法](#pd-forbidden) の禁止事項をすべて説明する。禁止されているのは
「装飾なのに構造のふりをする記法」だけである。

### <a id="pd-allowed"></a>許可する記法

<sub>`section` `pd-allowed`</sub>

| 記法 | 例 | 備考 |
|---|---|---|
| 段落 | 空行で区切る | 連続行は 1 段落として扱う |
| 箇条書き | `- 項目` / `* 項目` / `+ 項目` | ネストは非対応(平坦化される) |
| 番号付き箇条書き | `1. 項目` | HTML 射影は番号を振り直す。Markdown 射影は素通し |
| 引用 | `> 引用行` | 入れ子の引用は中身を再帰的に解釈する |
| 表 | 縦棒で区切った行 + 区切り行 | 区切り行がないとただの段落になる。列数は行ごとに自由 |
| コードブロック | バッククォート 3 つ、または `~~~` | 言語名を付けてよい |
| インラインコード | `` `code` `` | 中身は一切解釈されない |
| 強調 | `**太字**` / `*斜体*` | 純装飾。素通し |
| リンク | `[表示](URL)` | 外部リンク用。文書内リンクは参照記法を使う |
| 参照 | `@id` / `§id` | [参照は装飾ではない](#pd-refs) を参照 |

表以外のブロックは行頭で判定する。判定に使う記法(`-` `>` `1.` など)を
文字どおり書きたい場合はインラインコードに入れる。

### <a id="pd-forbidden"></a>禁止する記法

<sub>`section` `pd-forbidden`</sub>

| 記法 | なぜ禁止か | 起きること |
|---|---|---|
| 見出し(`#` 〜 `######`) | 階層はノードが持つ。散文に置くとノードの深さと二重定義になる | `canonicalize` が拒否する |
| 三連引用符だけの行 | 投影A/B ではその行が散文の終端そのもの | `canonicalize` が拒否する |

どちらも「書けてしまうと往復が壊れる」種類の記法である。禁止は好みではなく、
[検証はどこでかかるか](#pd-check) のとおり実際に検証される。

見出しを使いたくなったら、それは節を分けたいということなので、子ノードにする。
そのために型と ID があり、見出しの文字列より子ノードのほうが強い
(レンダラが見出しレベル・アンカー・目次を機械的に作れる)。

なお **コードフェンスの中は対象外**である。フェンス内の `#` はコメントや
Markdown の例示として自由に書いてよい。

### <a id="pd-refs"></a>参照は装飾ではない

<sub>`section` `pd-refs`</sub>

行内で唯一データモデルに参加する記法が参照である。

- `@id` と `§id` の 2 つだけを認める。意味は同じで、書き手の語感で選んでよい
- 直前が英数字・アンダースコアのときは参照と見なさない(メールアドレス対策)
- インラインコードとコードフェンスの中は参照ではない
- 抽出された参照は正準形の `refs[]` に出現順・重複除去で入る。派生値なので
  `.pyn` の表層には現れず、手で書くこともできない
- 参照先が存在しなければ `validate_refs` がエラーにする(リンク切れは CI で落ちる)

レンダラでの解決:

| 射影 | 出力 |
|---|---|
| HTML | `<a href="#id">参照先のタイトル</a>` |
| Markdown | `[参照先のタイトル](#id)` |

リンクテキストは参照先のタイトルから補完される。書き手がタイトルを書き写さないので、
改名しても表示が食い違わない。

### <a id="pd-text"></a>文字の扱い

<sub>`section` `pd-text`</sub>

- 散文の中身に**エスケープはない**。書いたものがそのまま入る
- 投影A では、開始行のインデントぶんだけ各行から取り除かれる(dedent)。
  開始位置より浅い行はエラーになる
- 空行はそのまま保持される。ただしブロック前後の空行は除去される
- 各行の行末の空白は除去される(`rstrip`)。Markdown の「行末 2 スペースで改行」は
  使えないので、改行したい場合は段落を分けるか箇条書きにする
- HTML 射影では生の HTML はエスケープされ、文字として表示される。
  Markdown 射影では素通しするため、閲覧環境によっては HTML として解釈されうる

### <a id="pd-check"></a>検証はどこでかかるか

<sub>`section` `pd-check`</sub>

| 規則 | 検証する場所 | いつ落ちるか |
|---|---|---|
| 見出しの禁止 | `canonicalize`(`pyn/model.py`) | 正準化のたび。つまり parse / patch / 射影生成のすべて |
| 三連引用符の行の禁止 | `canonicalize` | 同上 |
| 参照先の存在 | `validate_refs`(`pyn/refs.py`) | `python -m pyn check` / パッチ適用後 |
| 正準形の形 | `pyn/schema.py` と `schema/canonical.schema.json` | `python -m pyn check` |

許可された記法については、**構文エラーという概念がない**。表の区切り行が
足りなければただの段落になるだけで、文書としては妥当なままである。
検証されるのは「意味を持つ記法」だけ、という [原則: 検証できる意味だけを構造に置く](#pd-principle) の裏返しになっている。
